## 本轮验证发现并修正的问题

- 原命令行解析可能接受 `42oops` 这样的半个数字，并忽略 `--input` 中后续的非法内容。现在完整检查数值、范围、缺值以及相互冲突的命令。
- 摄像头成功打开但一帧也读不到时，现在返回失败，不再报告处理成功。
- HOG MeanShift 在重复运行时曾出现不同图片。OpenCV 4.13 的 `modules/objdetect/src/hog.cpp` 中，`HOGInvoker` 分别加锁追加检测框与权重，两个数组的对应顺序可能受调度影响。示例检测阶段临时单线程运行，之后恢复线程设置。验证脚本将 19.5 单独重复运行 3 次，与批量运行的结果逐一比较。
- 新验证脚本检查退出码和关键输出；缺文件、对比数据丢失或结果超出容差都会失败。每次使用新目录，避免读取上次残留图片。

## 复现

```powershell
.\build.cmd
.\verify.cmd
```

`verify.cmd` 在 `output/verification-日期-编号/` 保存 `logs/`、`images/`、`replay/` 和 `report.json`。最近一次报告为 `output/latest-verification.json`。没有模型时明确记为 `SKIP`；可显式用 `verify.cmd -SkipModels` 跳过模型测试。可选参数 `-Baseline 路径.json` 按 `{path, sha256}` 清单比较图片；文件哈希比较适用于相同构建环境。

可选的原 Python 对照：在独立 Python 环境安装 `scripts/requirements-verify.txt` 后执行：

```powershell
python scripts\compare_python.py --original E:\MyDownloads\cv40examples-main\cv40examples-main
```

脚本默认读取最近一次 C++ 验证目录；也可传 `--output 路径` 指定 `images/`。它运行原示例并比较六项像素结果、MCC 数值以及 HOG 检测框，保存 `python-comparison.json`，失败返回非零退出码。C++ 本身不需要 Python。

重构前的本机源码备份为 `build/readability-baseline.zip`，PNG 哈希快照为 `build/readability-baseline-images.json`。构建缓存、验证依赖、日志、输出和模型均在 Git 忽略范围内。
